# 异步编程与事件循环：JavaScript 是怎么同时做很多事的

很多人第一次接触 JavaScript 时都有一个困惑：为什么它在"等一个网络请求"的时候，页面还能继续响应点击、渲染动画？这要归功于 JavaScript 的事件循环（Event Loop）机制。

首先要知道，JavaScript 是单线程的。所谓单线程，指的是同一个时刻，JavaScript 引擎只能执行一段代码。如果这段代码要花 10 秒，那么这 10 秒里页面就会卡住，任何点击都没反应。所以，浏览器里跑的那些"等待"操作，比如发请求、读文件、定个 5 秒后的闹钟，根本不会在 JavaScript 主线程上排队等。

真正的机制是这样的：主线程把这类耗时操作"扔"给浏览器或运行环境（比如 Node.js）提供的其他部分去处理，然后主线程立刻空闲下来，继续处理用户事件。当那个操作完成时，会有一个"回调函数"被放进一个叫"任务队列"（Task Queue）的地方排队。主线程在处理完手头的代码后，会去看任务队列里有没有待办，有的话就取出来执行。

这套"不断检查队列、取出执行、再检查"的循环，就是事件循环。它保证了两件事：第一，主线程永远不被"等待"占用；第二，回调函数总会在合适的时机、按顺序被执行。

关于回调的执行时机，有一个关键概念叫微任务（Microtask）和宏任务（Macrotask）。微任务包括 Promise 的 then 回调、queueMicrotask、MutationObserver 等；宏任务包括 setTimeout、setInterval、I/O 事件、用户交互事件等。事件循环在一次"宏任务"执行完之后，会立刻把所有"微任务"清空，然后再去取下一个宏任务。这个顺序非常重要，它决定了代码的执行顺序。

举个具体的例子。执行下面这段代码：

```js
console.log('A');
setTimeout(() => console.log('B'), 0);
Promise.resolve().then(() => console.log('C'));
console.log('D');
```

同步代码会先依次打印 A、D。然后，setTimeout 的回调 B 是一个宏任务，会被排进宏任务队列；Promise 的 then 回调 C 是微任务，会被排进微任务队列。当前宏任务（也就是这段主代码）执行完毕后，事件循环会先清空微任务队列，打印 C；然后再从宏任务队列取出 B 打印。所以最终顺序是 A、D、C、B，而不是 A、B、C、D。

理解事件循环和微任务、宏任务的顺序，对写出没有时序 bug 的异步代码非常重要。常见的坑是：以为 setTimeout(fn, 0) 会"立刻"执行，其实它只是最快排进宏任务队列，仍要等当前同步代码和全部微任务跑完才会轮到它。
