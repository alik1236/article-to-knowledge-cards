# make-knowledge-cards

一个开源的 Agent Skill：把文章或笔记自动提炼成 **5–8 张知识卡片**，帮你把长文变成可学习、可复习的知识点清单。

## 1. 项目解决什么问题

读完一篇长文后，常见困扰是：信息太多记不住、抓不住重点、复习没有抓手。本项目解决"**文章太长、知识太散**"的问题——由 AI Agent 通读全文，只提取真正重要的知识点，压缩成一组结构统一的知识卡片，让学习、复习和分享都有清晰的载体。

## 2. 主要功能

- **正文/文件转卡片**：接受用户直接粘贴的文章，或本地 `.md` / `.txt` 文件路径。
- **四字段卡片结构**：每张卡片包含 **标题、核心知识、简明解释、例子或自测问题**，结构统一、可直接用于复习。
- **一张卡片一个知识点**：只提炼可独立成条的知识，拒绝把多个概念塞进一张卡。
- **自动去重**：删除重复与重叠内容，合并高度相似的知识点，丢弃无关细节。
- **忠于原文**：所有事实、数据、人名均来自输入；原文未明确的如实标注，绝不编造。
- **数量灵活**：目标 5–8 张；原文知识点不足时输出更少张数并说明原因，不强行凑数。
- **语言跟随**：输出语言默认与输入一致（中文输入输出中文）。
- **零依赖**：纯文本提炼，由 AI Agent 推理完成，不包含任何脚本和第三方依赖。

**暂不支持**：网页抓取、PDF 解析、Anki 导出、图形界面。

## 3. 安装方法

本项目是一个标准 Agent Skill，**安装 = 把技能目录放进运行环境支持的 Skill 根目录**，无需安装任何 Python 包。

1. 复制 `skills/make-knowledge-cards/` 整个目录到你的 Agent 环境的 Skill 根目录（例如 `workspace/.user_skills/`，具体以运行环境支持的 skill root 为准）：

   ```bash
   # 示例：把技能复制到用户技能根目录
   cp -r skills/make-knowledge-cards <your-skill-root>/
   ```

2. （可选）使用 Skill Creator 附带的官方校验工具验证安装结构：

   ```bash
   python <skill-creator>/scripts/quick_validate.py <your-skill-root>/make-knowledge-cards
   # 期望输出：Skill is valid!
   ```

3. 校验通过后，重启或刷新 Agent 会话，技能即可被自动发现并触发。

> 校验脚本需要 Python 环境及 `pyyaml` 模块（`python -m pip install pyyaml`）；Skill 本身运行不需要任何依赖。

## 4. 使用方法

安装后直接向 Agent 提出需求即可，技能会根据关键词自动触发：

- 「把这篇文章做成知识卡片」
- 「把 `notes/异步编程.md` 提炼成要点卡片」
- 「帮我从下面这段正文里提取知识点：……」

Agent 收到请求后按以下流程执行：

1. 完整读取用户粘贴的正文或指定的 `.md` / `.txt` 文件，不跳过任何段落；
2. 提取真正重要、可独立成条的知识点（一张卡片一个知识点）；
3. 去重、合并重叠内容、丢弃与主题无关的细节；
4. 按固定模板逐张生成卡片；
5. 控制数量在 5–8 张；信息不足时如实减少并说明原因。

输出格式：一句话总览 + 用 `---` 分隔的若干张卡片，每张卡片包含 `核心知识 / 简明解释 / 例子或自测问题` 三个字段（标题即卡片名）。

## 5. 输入输出示例

### 输入（节选，技术类文章）

> JavaScript 是单线程的，同一时刻只能执行一段代码。发请求、读文件等耗时操作被"扔"给运行环境处理，完成时回调进入任务队列。主线程处理完手头代码后，会检查队列取出执行——这套循环就是事件循环。回调分微任务（Promise then 等）和宏任务（setTimeout 等）；一个宏任务执行完，会先清空全部微任务，再去取下一个宏任务。

### 输出

**总览**：共提炼出 4 张卡片，覆盖单线程模型、事件循环、任务队列与微/宏任务顺序。

---

### 卡片1 · JavaScript 是单线程的

**核心知识**：JavaScript 引擎同一时刻只能执行一段代码，主线程被耗时任务占用时页面会卡住。

**简明解释**：单线程意味着没有并行计算，所有代码按顺序执行。理解这一点是理解事件循环的前提。

**自测问题**：如果 JS 是单线程的，为什么等网络请求时页面还能响应点击？

---

### 卡片2 · 耗时操作不占用主线程

**核心知识**：发请求、读文件等耗时操作被主线程"扔"给运行环境处理，完成时回调进入任务队列排队。

**简明解释**：主线程不亲自等待慢操作，而是委托给运行环境；操作完成后结果以回调形式回到队列，主线程空闲后再取走执行。

**例子**：`setTimeout(fn, 5000)` 只是登记一个 5 秒后的待办，主线程立即继续跑后面的代码。

---

### 卡片3 · 微任务与宏任务的区别

**核心知识**：回调分微任务（Promise then、queueMicrotask）和宏任务（setTimeout、setInterval、I/O、用户事件）两类。

**简明解释**：两者各自排队但优先级不同，这决定了异步代码的实际执行顺序。

**自测问题**：`Promise.resolve().then(cb)` 与 `setTimeout(cb, 0)` 分别把回调排进哪种队列？

---

### 卡片4 · 微任务先于下一个宏任务执行

**核心知识**：一个宏任务执行完后，事件循环先清空全部微任务，再去取下一个宏任务。

**简明解释**：这是执行顺序的关键规则。因此即使宏任务先被登记，排在微任务之后的下一个宏任务仍会晚于微任务执行。

**例子**：`A; setTimeout(B,0); Promise.then(C); D` 依次打印 A、D、C、B——B 虽先登记却被 C 抢先。

> 示例来自项目内 `tests/article-tech.md` 的真实测试输出；另有两篇测试文章 `tests/article-history.md`（历史类，7 张卡片）和 `tests/article-short.md`（信息稀疏类，按规则只输出 3 张并说明原因）可供参考。
